БЛОК B — Кнопки «Скачать Windows / Android» (установщики)
================================================================================
Цель: по клику на экране входа начиналась загрузка реальных файлов.

Уже задано в проекте (можно не менять, если имена файлов совпадают):
  web/public/client-downloads.json
    "windows": "/files/Messenger-Setup.exe"
    "android": "/files/app-release.apk"

Это ОТНОСИТЕЛЬНЫЕ пути: браузер откроет
  https://ваш-домен/files/Messenger-Setup.exe
  https://ваш-домен/files/app-release.apk


Шаг B.1 — Получить файлы на своём ПК
--------------------------------------
Windows (.exe):
  • Соберите Electron: в папке web выполните сборку установщика (как у вас настроено
    в package.json — часто npm run electron:dist). Готовый .exe переименуйте в
    Messenger-Setup.exe
  • Или временно положите любой тестовый .exe с этим именем, чтобы проверить ссылку.

Android (.apk):
  • Соберите APK (Android Studio или npm run android:apk:debug в web).
  • Переименуйте артефакт в app-release.apk (или измените имя в client-downloads.json).


Шаг B.2 — Положить файлы В ПРОЕКТ (у себя на компьютере)
---------------------------------------------------------
1) Откройте папку проекта:
     Мессенджер\web\public\files\
2) Скопируйте сюда ДВА файла:
     Messenger-Setup.exe
     app-release.apk
   (можно удалить или оставить PUT_INSTALLERS_HERE.txt — не мешает.)

3) Откройте терминал в папке web и выполните:
     npm run build

4) Проверьте на диске, что появилось:
     web\dist\files\Messenger-Setup.exe
     web\dist\files\app-release.apk
   Если файлов нет — проверьте, что они лежат в web\public\files\ ДО сборки.


Шаг B.3 — Залить сайт на Beget (файловый менеджер)
---------------------------------------------------
1) Войдите https://cp.beget.com
2) Меню: «Сайты» или список сайтов → выберите домен (sf-communication.ru).
3) Откройте «Файловый менеджер» / «Менеджер файлов».
4) Перейдите в КОРЕНЬ сайта, куда вы кладёте собранный мессенджер — туда же, где
   лежит index.html от Vite (часто это):
     ~/ваш-домен.ru/public_html/
   или подпапка, если сайт в подкаталоге — главное: тот же каталог, откуда открывается SPA.

5) Загрузите СОДЕРЖИМОЕ папки web/dist/:
   • index.html
   • папку assets/
   • папку files/ целиком (с .exe и .apk внутри)
   • client-downloads.json (в корне рядом с index.html)
   • остальные файлы из dist (favicon, manifest и т.д.)

   Удобно: локально заархивировать содержимое web/dist в zip, в панели Beget —
   «Загрузить» → распаковать, если панель умеет, или загрузить папки по отдельности.

6) Итог в корне сайта на хостинге должно быть:
     .../public_html/index.html
     .../public_html/client-downloads.json
     .../public_html/files/Messenger-Setup.exe
     .../public_html/files/app-release.apk


Шаг B.4 — Важно про nginx / прокси на Beget
--------------------------------------------
Если фронт и API на одном домене и nginx отдаёт только статику из public_html,
папка /files/ на диске должна реально существовать как public_html/files/ —
тогда URL https://домен/files/имя.exe отдаётся веб-сервером как файл.

Если у вас настроен прокси: ВСЕ запросы /files/ уходят на Node (как в SERVER_SETUP_BLOCKS.txt),
то файлы вложений хранятся не в public_html/files для установщиков — тогда либо:
  • кладите установщики в статику и настройте отдельный location только для этих имён, либо
  • укажите в client-downloads.json ПОЛНЫЕ ссылки на другой хост/CDN.

Для простого случая «всё в public_html» — достаточно папки files/ как в шаге B.3.


Шаг B.5 — Проверка (обязательно)
---------------------------------
В браузере (лучше режим инкогнито) откройте:
  https://sf-communication.ru/files/Messenger-Setup.exe
Замените домен на свой. Должно предложить «Сохранить файл», не HTML-страница и не 404.

Потом откройте страницу входа мессенджера → иконки Windows / Android — та же загрузка.

БЛОК C — Миграция базы данных (Prisma)
================================================================================
Цель: таблицы в PostgreSQL совпадают со схемой в prisma/.

Где запускать: там, где лежит папка prisma/ и рабочий .env с DATABASE_URL — обычно
сервер с Node-бэкендом, НЕ обязательно та же папка, что фронт на Beget.


Шаг C.1 — Убедиться в DATABASE_URL
-----------------------------------
В .env на сервере бэкенда строка вида:
  DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/ИМЯ_БД"

На Beget PostgreSQL часто создаётся в панели: «PostgreSQL» → база → пользователь —
там же показывают строку подключения. Скопируйте её в .env.


Шаг C.2 — Подключиться к серверу по SSH
----------------------------------------
Beget: в панели найдите «SSH» / «SSH-доступ» — включите, если выключено. Логин/хост/порт
указаны там.

С Windows: PuTTY или PowerShell:
  ssh логин@хост.beget.com


Шаг C.3 — Перейти в каталог проекта бэкенда
--------------------------------------------
Пример (путь у вас может отличаться):
  cd ~/ваш-домен.ru/messenger
или
  cd /var/www/messenger

Должны видеть папки prisma/, node_modules/ (или dist/), файл .env.


Шаг C.4 — Установить зависимости (если ещё не ставили на сервере)
-----------------------------------------------------------------
  npm install
  npx prisma generate


Шаг C.5 — Применить миграции
----------------------------
Одна команда:
  npx prisma migrate deploy

Успех: в выводе нет ERROR, есть применённые миграции.

Ошибки:
  • P1001 — не достучались до БД: проверьте DATABASE_URL, firewall, что PostgreSQL слушает нужный хост.
  • «permission denied» — пользователь БД без прав на схему public — выдайте права или используйте пользователя-владельца БД.


Шаг C.6 — Если бэкенд крутится не на Beget, а только БД на Beget
-----------------------------------------------------------------
Тогда migrate deploy можно запускать с ЛЮБОЙ машины, откуда доступен хост PostgreSQL
(иногда нужно разрешить внешний IP в настройках БД Beget):
  На ПК в папке проекта с .env:
    npx prisma migrate deploy


================================================================================
БЛОК D — Firebase / push (FCM)
================================================================================
Цель: на телефоне приходят push, когда приложение свёрнуто (после настройки ключа на сервере).

Шаг D.1 — Создать проект Firebase
-----------------------------------
1) https://console.firebase.google.com
2) «Добавить проект» / Add project → ввести имя → далее → (Google Analytics по желанию) → Создать.

Шаг D.2 — Добавить Android-приложение
---------------------------------------
1) На главной проекта нажмите значок Android (или «Добавить приложение» → Android).
2) Android package name (точно как в приложении):
     com.salesfactory.messenger
   (это из web/capacitor.config.ts, appId.)
3) app nickname — любой → «Зарегистрировать приложение».
4) Скачайте google-services.json → Сохраните.

Шаг D.3 — Положить google-services.json в проект
-------------------------------------------------
Локальный путь:
  web/android/app/google-services.json

Если файла не было — после копирования выполните в папке web:
  npx cap sync android

Затем пересоберите APK в Android Studio или gradlew assembleRelease/assembleDebug.


Шаг D.4 — Ключ для бэкенда (legacy Server key)
-----------------------------------------------
В Firebase: «Project settings» (шестерёнка) → вкладка «Cloud Messaging».

• В старых проектах был «Server key» в разделе Cloud Messaging API (Legacy).
• Если ключа нет: в Google Cloud Console для этого проекта включите
  «Firebase Cloud Messaging API», затем в Firebase снова откройте Cloud Messaging.

Скопируйте длинный ключ.

В .env на сервере бэкенда добавьте:
  FCM_SERVER_KEY=ВСТАВИТЬ_КЛЮЧ_БЕЗ_КАВЫЧЕК_ИЛИ_В_КАВЫЧКАХ_ЕСЛИ_СПЕЦСИМВОЛЫ

Перезапустите Node (pm2 restart …).

Без ключа: приложение может зарегистрировать устройство, но сервер не отправит push.


Шаг D.5 — iOS (по желанию)
---------------------------
В Firebase: Add app → iOS → Bundle ID (должен совпадать с Xcode).
В Apple Developer — ключ APNs, загрузка в Firebase — по мастеру Firebase для iOS.


================================================================================
БЛОК E — Если что-то не работает (краткий разбор)
================================================================================
Почта (A):
  • Нет писем — SMTP_* в .env, перезапуск Node, папка Спам, логи pm2 logs.

Скачивание (B):
  • 404 — нет файла в корне сайта в files/ или неверный регистр имён.
  • Открывается HTML вместо exe — nginx отдаёт index.html на все пути: нужен реальный файл
    или отдельный location для /files/.

База (C):
  • migrate deploy падает — DATABASE_URL, доступ с IP сервера к PostgreSQL.

Push (D):
  • Нет FCM_SERVER_KEY или неверный ключ; на iOS без APNs не придёт.
