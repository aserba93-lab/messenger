Как включить скачивание установщиков Windows (.exe) и Android (.apk) на экране входа
===================================================================================

Общая идея
----------
1. Файлы .exe и .apk должны лежать в интернете по адресам, которые открываются в браузере и начинают загрузку.
2. В файле client-downloads.json вы указываете эти адреса (или относительные пути на том же сайте).
3. После сохранения файла и обновления страницы кнопки на экране входа начнут открывать эти ссылки.

Важно: не вставляйте выдуманные домены вроде «ваш-домен.ru» — должен быть РЕАЛЬНЫЙ адрес вашего сайта или файлового хранилища.


Ошибка HTTP 404 на https://sf-communication.ru/files/app-release.apk
-------------------------------------------------------------------
Это значит: по этому URL файл на сервере не отдаётся.

  1) Убедитесь, что nginx для location /files/ проксирует на тот же Node, что и /graphql
     (см. SERVER_SETUP_BLOCKS.txt, блок 8).
  2) Положите файл на диск в каталог бэкенда:
        /var/www/messenger/public/files/app-release.apk
     (если проект в другом пути — подставьте свой корень репозитория + /public/files/).
     Сборка web/dist НЕ копирует .apk с вашего ПК автоматически — файл нужно залить на VPS отдельно.
  3) Имя файла должно совпадать с allowlist: по умолчанию в .env бэкенда
     PUBLIC_INSTALLER_FILES=Messenger-Setup.exe,app-release.apk
  4) После копирования: sudo systemctl restart messenger
  5) Проверка: curl -I https://sf-communication.ru/files/app-release.apk → должен быть 200.

Подробнее: web/public/files/PUT_INSTALLERS_HERE.txt


Часть A. Откуда взять файлы установщиков
----------------------------------------

Windows (.exe)
  • Если собираете Electron-сборку у себя на ПК: после сборки установщик обычно лежит в папке релиза проекта
    (например web/dist-electron, out/, release/ — смотрите README или скрипты сборки в репозитории).
  • Скопируйте готовый .exe в удобное место, переименуйте при необходимости, например: Messenger-Setup.exe

Android (.apk)
  • Соберите APK в Android Studio / Gradle или возьмите готовый артефакт из CI.
  • Либо вместо файла укажите ссылку на Google Play (см. ниже в разделе про JSON).


Часть B. Куда «залить» файлы на сервере (физически)
---------------------------------------------------

Нужно, чтобы по URL в браузере файл реально отдавался (скачивался), а не страница 404.

Вариант 1 — папка рядом с сайтом (часто так делают с nginx)
  См. ниже разделы «Панель хостинга» и «Linux + nginx».


--------------------------------------------------------------------------------
Б.1 Панель хостинга (Beget, Timeweb, REG.RU, ISPmanager и т.п.) — без команд в консоли
--------------------------------------------------------------------------------

Цель: чтобы в браузере открывалось:
  https://ВАШ-ДОМЕН.ru/files/имя-файла.exe

Шаги (названия кнопок могут чуть отличаться):

1) Войдите в личный кабинет хостинга под своим логином/паролем.

2) Откройте раздел вроде:
   «Сайты» / «Хостинг» → выберите домен (например sf-communication.ru)
   → «Файловый менеджер» или «Файлы сайта» / «Менеджер файлов».

3) Найдите КОРЕНЬ сайта — папку, где лежит index.html вашего мессенджера (часто это
   public_html, www, домен.ru, httpdocs — смотрите, куда вы заливаете dist после сборки).

4) Создайте папку:
   - кнопка «Создать папку» / «Новая папка» / значок «+»;
   - имя папки:  files   (латиницей, без пробелов).

5) Зайдите внутрь папки files.

6) Загрузите файлы:
   - кнопка «Загрузить» / «Upload» / значок стрелки вверх;
   - выберите с компьютера Messenger-Setup.exe и app-release.apk (или свои имена);
   - дождитесь окончания загрузки.

7) Проверка в браузере (обязательно):
   Откройте новую вкладку и в адресной строке вручную наберите:
     https://ВАШ-ДОМЕН.ru/files/Messenger-Setup.exe
   (подставьте свой домен и точное имя файла, как в менеджере.)
   Должно предложить «Сохранить файл» или начаться скачивание. Если 404 — см. ниже.

8) Пропишите в client-downloads.json (на ПК в проекте web/public, потом npm run build):

   "windows": "/files/Messenger-Setup.exe",
   "android": "/files/app-release.apk"

   или полные URL:
   "windows": "https://ВАШ-ДОМЕН.ru/files/Messenger-Setup.exe",
   "android": "https://ВАШ-ДОМЕН.ru/files/app-release.apk"

Почему может быть 404 в панели:
  • Файл залили не в тот корень (не туда, откуда открывается сайт).
  • Опечатка в имени файла или папки (Files вместо files — на Linux это разные папки).
  • Сайт открывается с подпути (редко): тогда путь может быть https://домен.ru/приложение/files/...


--------------------------------------------------------------------------------
Б.2 Сервер Linux (VPS) с nginx — команды и настройка
--------------------------------------------------------------------------------

Предположим:
  • Сайт (статика мессенджера) лежит в:  /var/www/sf-communication/dist/
  • Хотите отдавать установщики из:      /var/www/sf-communication/files/

1) Подключитесь по SSH (PuTTY, терминал):
     ssh пользователь@IP-адрес-сервера

2) Создайте папку и выставьте права (подставьте своего пользователя веб-сервера,
   часто www-data или nginx):

     sudo mkdir -p /var/www/sf-communication/files
     sudo chown -R www-data:www-data /var/www/sf-communication/files
     sudo chmod 755 /var/www/sf-communication/files

3) Загрузите файлы на сервер ОДИН из способов:

   А) С вашего ПК (SCP), из папки где лежат .exe и .apk:

     scp Messenger-Setup.exe app-release.apk пользователь@IP:/var/www/sf-communication/files/

   Б) Через SFTP (FileZilla): хост = IP или домен, логин/пароль → перейти в
      /var/www/sf-communication/files/ → перетащить файлы.

4) Настройте nginx, чтобы URL /files/ указывал на эту папку.

   Откройте конфиг сайта (часто /etc/nginx/sites-available/имя-сайта или
   /etc/nginx/conf.d/sf-communication.conf) в редакторе:

     sudo nano /etc/nginx/sites-available/sf-communication.ru

   Внутри блока server { ... } для HTTPS добавьте ОТДЕЛЬНЫЙ location (до или после
   location / для SPA):

     location /files/ {
         alias /var/www/sf-communication/files/;
         add_header Content-Disposition "attachment" always;
     }

   Важно:
   • В конце пути в alias обязательна косая черта /files/
   • Если у вас уже есть root на /var/www/sf-communication/dist/, не смешивайте:
     пусть /files/ отдаётся только через alias выше.

   Проверка конфига и перезапуск:

     sudo nginx -t
     sudo systemctl reload nginx

5) Проверка с сервера:

     curl -I https://sf-communication.ru/files/Messenger-Setup.exe

   Должен быть HTTP 200, не 404.

6) В client-downloads.json:

     "windows": "/files/Messenger-Setup.exe",
     "android": "/files/app-release.apk"

   или полные https://sf-communication.ru/files/...


--------------------------------------------------------------------------------
Б.3 Что именно «прописать», чтобы заработало в мессенджере
--------------------------------------------------------------------------------

На сервере нужно только ДВА условия:
  (1) Файлы по URL открываются в браузере и качаются.
  (2) В web/public/client-downloads.json указаны те же пути (или полные URL),
      затем выполнен npm run build и залит обновлённый dist на сервер.

Дополнительно в nginx ничего «для мессенджера» не требуется — кнопки просто
открывают ссылку из JSON.


Вариант 2 — другой домен или облако
  Можно выложить файлы на отдельный поддомен или S3/облако с публичной ссылкой.
  Тогда в JSON укажите полные https://... на эти файлы (как в браузере при проверке).


Как «залить» (что нажимать) — типично
  • FTP/SFTP (FileZilla, WinSCP): подключитесь к серверу → найдите корень сайта или папку public/www → перетащите .exe и .apk в папку files.
  • Панель хостинга (Beget, Timeweb, ISPmanager и т.д.): «Файловый менеджер» → открыть каталог сайта → создать папку files → «Загрузить» → выбрать файлы с компьютера.
  • После загрузки обязательно откройте в браузере прямую ссылку на файл и убедитесь, что файл качается.


Часть C. Что править в client-downloads.json
----------------------------------------------

Где файл в проекте (до выкладки)
  Путь:  web/public/client-downloads.json

Что копировать и куда вставлять
  1. Откройте файл в редакторе (VS Code, Notepad++ и т.д.).
  2. Найдите строки "windows" и "android".
  3. В КАВЫЧКИ после двоеточия вставьте ОДИН из вариантов ниже — свой реальный URL или путь.

Формат файла — валидный JSON:
  • Строки в двойных кавычках "..."
  • Между полями запятая
  • Последнее поле перед закрывающей скобкой } — без запятой в конце (если это единственное поле блока)

Пример с ПОЛНЫМИ ссылками (замените домен и имена файлов на свои):

{
  "windows": "https://sf-communication.ru/files/Messenger-Setup.exe",
  "android": "https://sf-communication.ru/files/app-release.apk"
}

Пример с ОТНОСИТЕЛЬНЫМИ путями (если файлы лежат на ТОМ ЖЕ домене, что и мессенджер):

{
  "windows": "/files/Messenger-Setup.exe",
  "android": "/files/app-release.apk"
}

Вместо файла APK — ссылка на Google Play:

{
  "windows": "https://sf-communication.ru/files/Messenger-Setup.exe",
  "android": "https://play.google.com/store/apps/details?id=com.example.messenger"
}

Сохраните файл (Ctrl+S).


Часть D. Сборка фронта и что выкладывать на сервер
-------------------------------------------------

На своём ПК в каталоге web выполните в терминале:

  npm run build

После этого появится папка web/dist/. Внутри будет:
  • index.html
  • assets/ (скрипты и стили)
  • client-downloads.json  ← скопирован из public/

Что залить на хостинг
  Залейте СОДЕРЖИМОЕ папки dist (или всю dist, в зависимости от настроек nginx) в корень сайта, откуда открывается мессенджер.
  Убедитесь, что на сервере лежит актуальный client-downloads.json рядом с index.html.

Если вы уже правите сайт на сервере напрямую
  Можно отредактировать client-downloads.json прямо в файловом менеджере хостинга — главное, чтобы путь был тот же, что отдаётся браузеру (часто /var/www/.../dist/ или корень сайта).


Часть E. Проверка в браузере
----------------------------

1. Откройте страницу входа мессенджера (ваш URL).
2. Обновите с принудительным сбросом кэша: Ctrl+F5 (Windows) или Cmd+Shift+R (Mac).
3. Нажмите иконку Windows или Android на экране входа.
4. Должна начаться загрузка или открыться Google Play. Если ошибка DNS или 404 — проверьте URL в JSON и что файл лежит на сервере.


Альтернатива: ссылки через .env при сборке (без правки JSON на сервере)
-----------------------------------------------------------------------

В каталоге web создайте или отредактируйте файл .env (если проект это поддерживает):

  VITE_DOWNLOAD_WINDOWS_URL=https://sf-communication.ru/files/Messenger-Setup.exe
  VITE_DOWNLOAD_ANDROID_URL=https://sf-communication.ru/files/app-release.apk

Затем снова выполните:

  npm run build

Ссылки попадут в собранный JS; client-downloads.json при этом может оставаться с пустыми строками, если приоритет у env задан в коде (см. логику приложения).


Частые ошибки
-------------

• DNS_PROBE_FINISHED_NXDOMAIN — в JSON указан несуществующий домен. Исправьте на реальный.
• 404 Not Found — файл не загружен в ту папку или неверное имя/регистр букв в имени файла.
• Старая ссылка в кэше браузера — сделайте Ctrl+F5.
